**ทำไมต้องมี:** วันใช้งานจริงวันแรกของสแกนหน้า (8 ก.ย. 69) สมบุญเช็คชื่อไม่ได้ทั้งวัน (10 ครั้ง) ทั้งที่มาทำงานจริง → หัวหน้าต้องมีทางแก้ทันทีโดยไม่ต้องรอแก้โค้ด กติกา "ไม่มีใครถูกบล็อก" ต้องมีทางหนีทีไล่ฝั่งแอดมิน

## หน้าใช้งาน

การ์ด **"✅ เช็คชื่อแทนเจ้าหน้าที่"** ในหน้า **วันหยุด (ปฏิทิน)** ของแอดมิน ใต้การ์ด "บันทึกลาแทน" (ไม่อยู่บนแดชบอร์ด — แดชบอร์ดจองไว้ทำวิดเจ็ต)
- เลือกชื่อ · ประเภท (เช็คชื่อเช้า / ลงเวรกลางคืน) · วันที่ (default วันนี้ · `max=วันนี้` กันอนาคต · ประเภทเวรคืน label เปลี่ยนเป็น "คืนวันที่" = duty_date) · ติ๊กสาย (เฉพาะเช้า — ซ่อนเมื่อเลือกเวรคืน) · หมายเหตุ
- ใต้ปุ่ม = รายการที่เช็คแทนไว้ 30 วันล่าสุด (เช้า+เวรคืนรวมกัน) กด **ลบ** ได้ (Swal ยืนยัน) — ลบแล้ววันนั้นกลับเป็น "ยังไม่มา/ขาด"

## Backend (`app/handlers/admin.php` ท้ายไฟล์ · action `proxy_checkin` / `proxy_list` / `proxy_del`)

- **คอลัมน์ `by_admin TINYINT(1)`** ใน `attendance` และ `night_shifts` (migrate อัตโนมัติใน `db.php` — probe ที่ `attendance.by_admin` ตัวเดียวคุมทั้งสองตาราง) — ทุกที่ที่อ่าน roster ส่งค่านี้ออกมาด้วย (`roster_for`, `holidayWorkers`, night tonight/`h_night_roster`; `h_my_history` ใช้ `SELECT *` ได้ฟรี)
- **`h_proxy_checkin`** ข้าม GPS/เซลฟี่/ใบหน้าทั้งหมด (`face_flag=0`, lat/lng/selfie NULL) · กติกาที่**ยังใช้เหมือน จนท. กดเอง**: วันหยุดสถานีเช็คได้ก็ต่อเมื่อ `sunday_work_enabled` หรือเป็นวันนอกสถานที่ · มีใบลาวันนั้น = ปฏิเสธ (บอกให้ลบใบลาก่อน ไม่ทับให้เอง) · ซ้ำ = ปฏิเสธ · เวรคืน = เปิดระบบ + ชายเท่านั้น
- **สาย/ตรงเวลา แอดมินเลือกเอง** (`late` param) ไม่คำนวณจากเวลา — เพราะเวลาที่กดแทนไม่ใช่เวลาที่คนนั้นมาถึงจริง · **ไม่มี** ยกเว้นสายจากเวรคืน (แอดมินตัดสินเอง)
- **เวลาเข้า:** วันนี้ = `date('Y-m-d H:i:s')` ตอนกด · **วันย้อนหลัง = `"$date " . checkin_open . ":00"`** (เช้า) หรือ `night_checkin_open` (เวรคืน) — **ห้ามใช้ `NOW()` กับวันย้อนหลัง** จะได้เวลาของวันนี้ปนวันเก่า (กระทบ `avg_in` ในอันดับ)
- แจ้งเจ้าตัวผ่าน `notify_push(..., 'announcement', ...)` — ใช้ type `announcement` เพราะ `notifications.type` เป็น ENUM 3 ค่า ไม่อยากเพิ่ม migration ENUM
- **`h_proxy_del` = `DELETE ... WHERE id=? AND by_admin=1`** — เงื่อนไข `by_admin=1` คือกำแพงทั้งหมดของ endpoint นี้ (ทดสอบแล้ว: ยิง id ของแถวที่ จนท. เช็คเอง → "ไม่พบรายการ" แถวอยู่ครบ) · `rowCount()` บอกว่าลบจริงไหม
- คะแนนความขยัน/นับยอด **นับแถว by_admin เป็นเช็คชื่อปกติ** ไม่กรองออกที่ไหน (ตั้งใจ — คนมาจริงแต่แอปพังไม่ควรเสียคะแนน)

## Frontend

- `proxyChip(r)` (admin.js ข้าง `faceFlagChip`) → `<span class="face-flag f2">👤 หัวหน้าเช็คให้</span>` ใช้ style เดิม ไม่เพิ่ม CSS · ใส่ใน `rosterGroup` (แดชบอร์ด) + `nightRosterBody` · ฝั่ง จนท. `historyCard` + บล็อกเวรคืนใน `vHistory` (app.js) เขียน inline ไม่เรียก helper ข้าม script
- **กับดักที่เจอตอนเทส:** `vDash()` วาดจาก `App.adminData` ที่ cache ไว้ตอนเข้าแอป — `proxyAdd`/`proxyDel` ต้อง `App.adminData = await App.api('admin_data')` ก่อน `vDayoff()` (เหมือน `leaveAct`) ไม่งั้นสลับไปแดชบอร์ดยังเห็น "ยังไม่มา" ทั้งที่ DB มีแถวแล้ว
- **กับดักที่สอง (เทส local):** sw.js cache-first — แก้ admin.js หลังเปิดหน้าครั้งแรกของ v ใหม่แล้ว เบราว์เซอร์ยังได้ไฟล์เก่าจาก cache แม้ reload ต้อง `caches.delete` + unregister SW (หรือเด้ง v อีกรอบ) ก่อนเทสซ้ำ

## วิธีเทสซ้ำ (curl กับ `php -S 127.0.0.1:8123` token แอดมินใน `X-Auth-Token`)

เช้าวันนี้ → roster `by_admin=1` state ตาม late · ซ้ำ → fail · ย้อนหลัง → `time_in = "<date> <checkin_open>:00"` · วันที่มีใบลา → fail บอกให้ลบใบลา · อนาคต → fail · `kind` มั่ว → fail · user แอดมิน → "ไม่พบเจ้าหน้าที่" · เวรคืนหญิง → fail · เวรคืนย้อนหลัง → `time_in = "<date> 18:00:00"` · `proxy_del` id ปกติ → fail แถวอยู่ · `my_history` ของ จนท. มี `by_admin` + `notify_list` มีข้อความ · ล้าง: `DELETE FROM attendance WHERE by_admin=1` (local เท่านั้น)
